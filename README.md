## 🧭 Зачем это нужно

У среднего хантера в работе **10–40 проектов одновременно**: где-то нужно сделать свап в тестнете, где-то поставить стейк, где-то не пропустить окно клейма. Всё это живёт в заметках, таблицах и тридцати вкладках браузера.

**DropTrack** собирает рутину в одну панель:

- 🎯 интерактивные чек-листы активностей по каждому проекту;
- ⏰ ежедневные задания («дейли») **автоматически обнуляются в 03:00 МСК**;
- 📅 все дедлайны регистрации и клеймов — в календаре с экспортом в Google Calendar;
- 📊 аналитика портфеля: статусы, блокчейны, категории, рейтинг фондов, суммарные инвестиции.

## ✨ Возможности

### 🛡️ Личный кабинет и RBAC
- [x] Разделение прав: мутации доступны только авторизованному администратору
- [x] 3-шаговое восстановление пароля: запрос одноразового 6-значного кода на Email → ввод кода → установка нового пароля
- [x] Повторная отправка кода с кулдауном, блокировка после 5 неудачных попыток
- [x] Смена пароля в окне профиля с проверкой текущего

### 🎯 Проекты и активности
- [x] Полная карточка проекта: название, тикер (`$MON`), сайт, логотип (URL или загрузка файла **до 2MB**), описание с живым счётчиком **до 500 символов**, категории и теги
- [x] Чек-лист заданий 9 типов: Тестнет, Мейннет, Стейкинг, Ликвидность, Торговля, Рефералы, Соцсети, Дейли, Прочее — с прямыми ссылками и отметками выполнения
- [x] Флаг «Сброс каждые 24ч» для ежедневных активностей
- [x] Инвесторы и раунды: венчурные фонды с тирами **Tier 1 / Tier 2**, суммами в USD и датами раундов
- [x] Токеномика: интерактивная круговая диаграмма (Recharts) с жёсткой валидацией распределения долей **ровно на 100%**, стандартом токена и Total Supply

### ⏰ Автоматический сброс в 03:00 МСК
- [x] Встроенный cron-планировщик: каждые сутки в **03:00 по Москве (UTC+3)** обнуляет выполненные чекбоксы активностей с флагом «24ч»
- [x] Если приложение было закрыто в момент сброса — catch-up сброс выполняется при следующем открытии
- [x] Живой таймер обратного отсчёта в шапке и в операционной панели
- [x] Ручной принудительный сброс (только админ) и журнал истории всех сбросов

### 🔍 Поиск, фильтры, умная сортировка
- [x] Мгновенный полнотекстовый поиск по названию, тикеру, описанию и тегам
- [x] Фильтры: статус наград, типы вознаграждений, прогресс (0–25% … 100%), блокчейн, тир инвесторов, категория, горящие дедлайны (≤7 дней)

## 🛠️ Стек

| Слой | Технология | Зачем |
|---|---|---|
| Frontend | React 18 + TypeScript | типизированные модели проектов, активностей, токеномики |
| Стили | Tailwind CSS 4 | дизайн-токены двух тем, utility-first компоненты |
| Иконки | Lucide React | единая графическая система |
| Анимации | motion/react | scroll-reveal, spring-hover, анимация прогресса |
| Графики | Recharts | пай-чарт токеномики, бар-чарты аналитики |
| Праздник | canvas-confetti | салют при 100% выполнения проекта |
| Сборка | Vite 6 | мгновенный HMR, production-бандл |
| Хранилище | Встроенная JSON-база | атомарная персистентность в localStorage (маппинг на `/data/*.json`) |

### 💾 Архитектура данных

| Ключ хранилища | Аналог на сервере | Содержимое |
|---|---|---|
| `droptrack_projects_v1` | `/data/projects.json` | JSON-база проектов, активностей, инвесторов, токеномики |
| `droptrack_reset_log_v1` | `/data/reset_logs.json` | журнал автоматических и ручных сбросов |
| `droptrack_admin_v1` | — | аккаунт администратора (хэш пароля) |
| `droptrack_session_v1` | — | активная сессия администратора |
| `droptrack_favs_v1` | — | личное избранное посетителя |
| `droptrack_theme_v1` | — | выбранная тема интерфейса |

Все мутации проходят через централизованный стор с атомарной записью — интерфейс никогда не расходится с данными. Cron-механика сравнивает текущее время с `next_reset` (ближайшие 03:00 МСК) каждые 20 секунд и при пропуске выполняет отложенный сброс с записью в журнал.

## ❓ FAQ

<details>
<summary><b>Как работает сброс в 03:00, если приложение было закрыто?</b></summary>
<br/>
Планировщик хранит момент ближайшего сброса. При загрузке приложения и далее каждые 20 секунд время сравнивается с ним: если момент прошёл — выполняется catch-up сброс с пометкой «авто» в журнале. Данные при этом не теряются.
</details>

<details>
<summary><b>Куда приходит код восстановления пароля?</b></summary>
<br/>
В демо-сборке код отображается в панели «Симуляция письма» прямо в модальном окне (без реального SMTP код было бы невозможно получить). Архитектура сервиса <code>requestResetCode</code> рассчитана на замену на реальную отправку письма.
</details>

<details>
<summary><b>Как добавить события в Google Calendar?</b></summary>
<br/>
Вкладка «Календарь» → кнопка «Экспорт .ics» → в Google Calendar: <i>Настройки → Импорт и экспорт → Импорт</i>. Файл содержит все дедлайны регистрации и клеймов с напоминаниями.
</details>

<details>
<summary><b>Как полностью сбросить локальные данные?</b></summary>
<br/>
Откройте DevTools → Console и выполните <code>localStorage.clear()</code>, затем перезагрузите страницу — база пересоздастся из сида.
</details>
